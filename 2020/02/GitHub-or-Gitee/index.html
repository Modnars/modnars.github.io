        如题，在中国，代码托管选择 GitHub 还是 Gitee 呢？

        假期在家，发现GitHub的访问速度越来越慢了。甚至，我的 iPad 直接无法访问 GitHub 了… 这就导致我 iPad 的两个 GitHub 代码阅读APP直接崩溃…

        再就是使用电脑上的 Google Chrome 和 Safari 访问巨慢无比的 GitHub，图片常常因为获取超时而加载不出来。当然，尝试修改 hosts 文件来加速 DNS 解析也无果。

        终于，我打算试试 Gitee（码云）了…

        之前听说过这个，说这是国内做得不错的代码托管工具。天时地利，当然，盘它！

        然后就注册了一个，直接用的 Modnar 作为用户名（看到这儿还不去 Follow+Star?! 疯狂暗示），后来发现这和我的本地 git 配置不同名。于是 Gitee 上的每个 repo 的贡献者，都是 2 人… 小问题，忽略（强迫症的我握紧了拳）。

        需要说一下的是，Gitee 可以为每个 repo 提供 Pages 服务，当然，如果想用 username.gitee.io 作为域名访问的话，你的这个 repo 名必须直接是你的 username，否则该 repo 得到的 Pages 链接会是 username.gitee.io/pagesname/ 的格式，这就引出了下面的问题：

        留个问题：

能否部署同一个 Hexo 项目到不同的 URL 而不仅仅是 git 仓库？具体一些，能否找到一种解决途径，不修改上述的 username.gitee.io/pages/ 情况而达到同时部署多个URL？

后来

        我发现 Gitee 提供的 Pages 服务有点鸡肋，具体表现在每次 push 之后，要进入 Pages 服务点击更新来重新部署，不如 GitHub 提供的自动部署服务好。

        其次，Gitee 提供的 Pages 似乎对移动端浏览器支持得不好？我在上次修改本博客后，在电脑端浏览器分享了本博客，后来发现移动端 Gitee Pages 打不开 😶

        最后… 今天 GitHub 浏览速度快了不少…
